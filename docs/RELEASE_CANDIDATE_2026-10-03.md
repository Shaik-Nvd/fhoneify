## Implemented behavior

- Exact variant, supported condition and a matching coefficient are insufficient: a candidate now requires a fresh exact Cashify repository reference, source/confidence/identity metadata, the validated reference amount, a fresh `OK` stored profile and explicit dated exact-variant conditional route evidence. The invented 5% reference tolerance and fabricated fixed routes were removed. Missing/unrecognized modes remain `UNKNOWN`; they never become `NOT_ASKED`.
- Route inputs include warranty, GST bill, age, box, charger, S Pen and eSIM. A separate server-only reviewed JSON input is loaded only when explicitly configured with `PRICING_RELEASE_ROUTE_EVIDENCE_FILE`. No fixture is implicitly activated at runtime. Both stored-profile and trace agreement are required.
- Accessory accounting uses the measured candidate's own baseline. The box value is not added a second time. All-three-ownership-questions `NOT_ASKED` alone no longer authorizes a correction on unmeasured devices. Candidate missing-accessory conditions require inspection; no missing-accessory deduction was invented.
- Each individual selected fault is counted, including each hardware failure and each body/display subtype. Six functional faults cannot become one benign functional category. Unknown options, inconsistent parent/subtype selections, nonworking calls, contradictory accessories and mutually exclusive battery answers are rejected.
- For exact Note 15 Pro Plus 12/512, even single hardware faults are refused by this release adapter: verified Wi-Fi/fingerprint losses expose unsafe legacy fallback. The prior narrow additive research candidate, its component deductions and failed results remain intact. The legacy aggregate cap was not removed or modified.
- Apple iPhone 12 Pro's research baseline exceeds its measured Get Upto. Its preview remains available, but this binding release adapter requires a separate headline-compatibility decision and currently refuses it.
- The new Xiaomi 14 Ultra 16/512 clean control exposes ₹9,030 legacy baseline overpayment even with correct NOT_ASKED routing. That exact variant is now quarantined from RC legacy fallback before any future reference/profile update. No new baseline coefficient is fitted to this control.
- Inspection decisions return HTTP 422 with no binding price or quote token. The nonbinding context supplies the verified questionnaire and headline to allow answer review. The frontend displays **Inspection required**, suppresses scheduling, clears rejected saved prices and preserves route metadata through Recalculate, Review answers and reload.
- Lead verification enforces current eligibility **before** accepting an old token. Pricing-mode/release-version changes recompute under the current decision; an old signed legacy offer cannot bypass inspection. Historical same-mode legacy token locking remains unchanged. The bucket endpoint also delegates real answers to the authoritative service in RC mode and cannot use its former multiplier as a bypass.
- Audit output records reference, questionnaire semantics, selected rule/decision, accessory basis, route evidence hash, token pricing version and active pricing version. RC version is `fhoneify-pricing/2026-10-01-xiaomi-inr-functional-cap+rc-verified-inputs-v3-2026-10-03`; v3 records the additional Ultra guard.

`calculateFhoneifyPrice`, the production engine, uplift tiers/minimum/cap, ₹99 fee, payout rounding, weekly refresh and seed catalog are unchanged from `b072b90`. The Note 10 Pro Max broad-change revert and 15 unpriced pending Redmi variants are preserved.
